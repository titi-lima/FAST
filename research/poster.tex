\col{%
\heading{What FAST is}
\textbf{FAST} stands for \emph{FAST Approaches to Similarity-based Testing}, introduced by Breno Miranda and coauthors at ICSE 2018. It is a family of test case prioritization algorithms based on one principle: execute tests that are most \emph{dissimilar} from the tests already selected.
\begin{itemize}\tight
  \item Each test is represented as a set: black-box identifiers/content or white-box coverage features.
  \item MinHash compresses those sets into compact signatures that preserve similarity estimates.
  \item Locality-sensitive hashing finds diverse candidate tests quickly instead of comparing every pair.
  \item Variants such as \textbf{FAST-pw}, \textbf{FAST-sqrt}, and \textbf{FAST-one} trade search effort for speed.
\end{itemize}

\vspace{0.14in}
\heading{Why it needs a tool}
FAST approaches scaled similarity-based prioritization to a million tests, yet stayed a research prototype. Three barriers blocked everyday CI use:
\begin{itemize}\tight
  \item \textbf{Integration friction} --- test representations and orchestration done by hand.
  \item \textbf{No incrementality} --- unchanged tests reprocessed on every run.
  \item \textbf{Framework fragmentation} --- pytest, Vitest, Go test, and JUnit each differ.
\end{itemize}

\vspace{0.14in}
\heading{What fast-tcp does}
It packages FAST as a drop-in local tool. Framework integrations collect tests, the FAST engine computes the order, and a lightweight snapshot layer puts \textbf{new and modified tests first}. It runs entirely locally and needs no historical failure data.

\vfill

\heading{How it works}
\begin{center}\includegraphics[width=0.96\linewidth]{figures/architecture.png}\end{center}
\vspace{0.04in}
\begin{itemize}\tight
  \item \textbf{Framework plugins} collect tests and extract black-box representations.
  \item \textbf{Snapshot cache} in \texttt{.fast/snapshot.git} stores file hashes as Git trees.
  \item \textbf{FAST engine} ranks by dissimilarity via MinHash\,+\,LSH.
\end{itemize}

\vfill

\heading{Incremental by design}
Each run diffs the workspace, so only \emph{new} work is prioritized:
\begin{enumerate}\tight
  \item Diff against the previous snapshot.
  \item Partition tests into \textbf{new\,/\,unchanged\,/\,deleted}.
  \item Rank new \& modified tests first with FAST.
  \item Seed the cumulative signature, then rank the unchanged tests.
\end{enumerate}
The snapshot is independent of the project's own Git history, so it works even with uncommitted changes. Variants trade effort for speed: \textbf{FAST-pw} (most dissimilar pick), \textbf{FAST-sqrt} ($\sqrt{n}$ budget), \textbf{FAST-one} (single candidate).

\heading{Takeaways}
\begin{itemize}\tight
  \item FAST becomes a real local tool with maintained framework integrations.
  \item Git-backed snapshots make repeated prioritization incremental.
  \item Overhead is sub-second on real suites; ranking itself stays in milliseconds.
\end{itemize}
